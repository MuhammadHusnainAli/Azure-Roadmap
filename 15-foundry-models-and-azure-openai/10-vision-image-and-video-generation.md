# Vision, Image and Video Generation

## Why it matters

Images and video are now first-class inputs and outputs. Vision-capable models read screenshots, charts, photos and scanned pages. Image models generate and edit marketing visuals and product mock-ups. Video models produce short clips. Each has its own API shape, limits, costs, content safety behaviour and responsible-use obligations. This file is the practical guide to using them on Foundry. Topic 13 file 05 covers the concepts.

## Key concepts

### Image understanding (vision input)

| Aspect | Detail |
|---|---|
| Models | GPT-4o, GPT-4.1, GPT-5.x, GPT-6 families, the model router and many partner models accept image input |
| How to send | Image URL or base64 data URL in a message content part (`image_url` in Chat Completions; `input_image` in Responses) |
| `detail` | `low` (fixed small token cost), `high` (tiles at higher resolution, more tokens), or `auto` |
| Limits | Per-request image counts and size limits apply (for example GPT-4o and GPT-4.1 allow up to 50 images per request); check the model's limits |
| Cost | Images are converted to tokens; cost scales with resolution and detail |

### Image generation and editing (checked 2026-11)

| Model family | Provider | Notes |
|---|---|---|
| `gpt-image-1`, `gpt-image-1-mini`, `gpt-image-1.5`, `gpt-image-2`, `gpt-image-2.5-flare`, `gpt-image-2.5-sunburst` | OpenAI (sold by Azure) | Text-to-image and image editing (with input images and masks); prompts up to 4,000 characters; default quotas around 9–12 requests per minute |
| `MAI-Image-2.5` / `2.5-Pro` / `2.5-Flash`, `MAI-Image-2.6` / `2.6-Flash` | Microsoft (Preview) | Text-to-image and image-to-image editing with up to five input images; pixel-count limits per model |
| `FLUX.2-pro`, `FLUX.2-flex`, `FLUX.1-Kontext-pro`, `FLUX-1.1-pro` | Black Forest Labs (sold by Azure) | High-quality generation and context-aware editing |
| DALL·E 3 | OpenAI | Legacy; superseded by gpt-image models (check retirement schedule) |

Common parameters for gpt-image models: `prompt`, `size` (for example `1024x1024`, `1536x1024`, `1024x1536`), `quality` (low, medium, high), `n`, `output_format` (png, jpeg, webp), `background` (transparent where supported), and for edits an `image` (one or more) plus optional `mask`. Output is returned as base64. Check each model's parameter table, because they differ.

### Video generation

| Model | Status | Notes |
|---|---|---|
| `sora-2` | **Preview** | Text-to-video (and image-to-video where supported); prompts up to 4,000 characters; asynchronous **job** model; default quota of 2 job requests per minute |

Video generation is asynchronous: create a job, poll its status, then download the content. Resolution, duration and audio options are model-specific. Generated videos are subject to content filtering and should be labelled as AI-generated.

### Content safety and provenance

- Image and video prompts **and** outputs pass through content filters (sexual, violence, hate, self-harm) and protections against generating certain public figures and copyrighted characters. Blocked requests return errors with filter details.
- Images generated by Azure OpenAI image models include **Content Credentials** (C2PA provenance metadata) indicating AI generation.
- Some image and video models require registration or have limited regions.

## How it works on Azure

### Vision input (Responses API)

```python
r = client.responses.create(
    model="<vision-capable-deployment>",
    input=[{"role": "user", "content": [
        {"type": "input_text", "text": "List every error message visible in this screenshot as JSON."},
        {"type": "input_image", "image_url": "https://<storage>.blob.core.windows.net/shots/err.png?<user-delegation-sas>", "detail": "high"}]}])
print(r.output_text)
```

If you pass a URL, the service must be able to fetch it. For private data, send base64 instead of exposing storage publicly, or use a short-lived user delegation SAS.

### Generate and edit images

```python
import base64

gen = client.images.generate(
    model="<gpt-image deployment>",
    prompt="Isometric illustration of a smart warehouse with autonomous robots, brand colours navy and teal",
    size="1536x1024", quality="medium", n=1)
open("warehouse.png", "wb").write(base64.b64decode(gen.data[0].b64_json))

edit = client.images.edit(
    model="<gpt-image deployment>",
    image=open("warehouse.png", "rb"),
    prompt="Add a teal company logo on the largest robot",
    size="1536x1024")
open("warehouse-logo.png", "wb").write(base64.b64decode(edit.data[0].b64_json))
```

The Responses API also offers an **image generation tool**, so a conversational model can create or edit images as part of a multi-turn exchange.

### Video job (sketch)

```python
job = client.videos.create(model="<sora-2 deployment>", prompt="A drone shot over a misty pine forest at sunrise", seconds="8")
# poll: client.videos.retrieve(job.id) until status is completed, then download the content
```

Method names, parameters (`size`, `seconds`) and paths for video generation are evolving while `sora-2` is in preview. Use the current video generation how-to for exact calls.

## Design decisions and trade-offs

| Decision | Guidance |
|---|---|
| Vision LLM vs document services | Vision LLMs for flexible reasoning over images; Content Understanding or Document Intelligence for high-volume structured extraction |
| Detail level | Low by default; high only when small text or fine detail matters |
| Image model choice | gpt-image for instruction following and text rendering; MAI-Image or FLUX for specific styles or editing; compare on your brand guidelines |
| Generation vs stock or design | Use generation for ideation and variants; keep human design review for published assets |
| Video in production | Preview status means changing APIs and limits; use for experiments and internal content first |

## Hands-on

1. Send the same chart image at `low` and `high` detail and compare answers and token usage.
2. Generate three images with a gpt-image deployment at different quality settings; compare latency and cost.
3. Edit an image with a mask to replace only part of it.
4. Inspect the Content Credentials metadata of a generated image with a C2PA viewer.
5. If you have access, create a short `sora-2` video job and poll it to completion.

## Security, cost and reliability notes

- **Security:** images can carry prompt-injection text. Treat extracted text as untrusted.
- **Security:** don't expose private images through public URLs for vision calls; prefer base64 or short-lived SAS.
- **Responsible AI:** label AI-generated media, avoid real people's likenesses without consent, respect brand and copyright policies, and keep a human in the loop for published content.
- **Cost:** high-detail vision, high-quality images and video are expensive. Cache generated assets and right-size quality.
- **Reliability:** low default RPM quotas for image and video models; queue requests and handle 429s and content-filter rejections gracefully.

## Common mistakes

- Sending full-resolution photos at high detail for simple questions.
- Expecting identical images for identical prompts.
- Publishing generated images without review or labelling.
- Building production features on preview video APIs without a fallback.
- Ignoring the per-minute request limits for image models.
