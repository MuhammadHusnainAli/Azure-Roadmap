# Responsible AI Dashboard

## Why it matters

A model with 92% accuracy can still fail badly for a particular region, age band or product line, rely on a feature it shouldn't, or produce decisions nobody can explain to a regulator or a customer. For predictive models used in credit, hiring, insurance, healthcare or public services, you need evidence of **where** the model errs, **whether** it treats groups fairly, and **why** it makes each prediction. Azure ML's **Responsible AI (RAI) dashboard** brings mature open-source tools into one interface and a shareable scorecard, supporting both debugging and governance ([Topic 23](../23-responsible-ai-security-and-governance/README.md)).

## Key concepts

### Components

| Component | Question it answers | Underlying tools |
|---|---|---|
| **Error analysis** | Where are errors concentrated? Which cohorts (subgroups) fail? | Error Analysis (tree map, heat map) |
| **Model overview and fairness** | How does performance differ across groups defined by sensitive features? | Fairlearn metrics (disparities in accuracy, selection rate, error rates) |
| **Data analysis** | Is the data over- or under-representing groups? How do predictions relate to features? | Data explorer |
| **Model interpretability** | Which features drive predictions globally and for an individual case? | InterpretML / SHAP-based explainers |
| **Counterfactual what-if** | What minimal change would flip this prediction? What happens if I perturb a feature? | DiCE |
| **Causal analysis** | What is the causal effect of a treatment feature on a real outcome (using historical data)? | EconML |

You can include only the components relevant to your case.

### Identify → diagnose → mitigate

| Stage | Components |
|---|---|
| **Identify** | Error analysis, fairness analysis, model overview |
| **Diagnose** | Data analysis, interpretability, counterfactuals |
| **Mitigate** | Outside the dashboard: rebalance data, feature changes, Fairlearn mitigation algorithms, thresholds per group, human review |

### Responsible decision-making

- **Data-driven insights** via causal inference ("what would a promotion do to revenue?").
- **Model-driven insights** via counterfactuals ("what could this applicant change to be approved?"), useful for recourse explanations.

### Scorecard

The **RAI scorecard** is a PDF summary of performance, fairness, data and explanation findings against targets you set, for sharing with non-technical stakeholders, risk and compliance teams, and auditors.

### Scope

The dashboard targets **tabular** classification and regression models in Azure ML (MLflow models), with image and text dashboards in the open-source Responsible AI Toolbox. For **generative AI**, use Foundry evaluations, safety evaluators and red teaming instead ([Topic 22](../22-evaluation-observability-and-genaiops/README.md)).

## How it works on Azure

The dashboard is generated by a **pipeline of RAI components** from the `azureml` registry:

| Component | Role |
|---|---|
| RAI Insights dashboard constructor | Takes the model, train and test data, target column, task type |
| Add Error Analysis / Explanation / Counterfactuals / Causal | Add each tool |
| Gather RAI Insights dashboard | Assembles results |
| Generate RAI scorecard | Optional PDF with your targets |

```python
from azure.ai.ml import MLClient, Input
from azure.ai.ml.dsl import pipeline
from azure.identity import DefaultAzureCredential

ml = MLClient(DefaultAzureCredential(), "<sub>", "rg-ml", "mlw-churn-dev")
reg = MLClient(DefaultAzureCredential(), registry_name="azureml")
v = "latest"
construct = reg.components.get(name="microsoft_azureml_rai_tabular_insight_constructor", label=v)
erroran   = reg.components.get(name="microsoft_azureml_rai_tabular_erroranalysis", label=v)
explain   = reg.components.get(name="microsoft_azureml_rai_tabular_explanation", label=v)
gather    = reg.components.get(name="microsoft_azureml_rai_tabular_insight_gather", label=v)

@pipeline(default_compute="serverless")
def rai_pipeline(train, test):
    c = construct(title="Churn RAI", task_type="classification",
                  model_input=Input(type="mlflow_model", path="azureml:churn-model:5"),
                  train_dataset=train, test_dataset=test, target_column_name="churned",
                  categorical_column_names='["region","plan"]',      # JSON-encoded string
                  maximum_rows_for_test_dataset=5000, classes="[]")
    e = erroran(rai_insights_dashboard=c.outputs.rai_insights_dashboard)
    x = explain(rai_insights_dashboard=c.outputs.rai_insights_dashboard, comment="global and local")
    gather(constructor=c.outputs.rai_insights_dashboard,
           insight_1=e.outputs.error_analysis, insight_2=x.outputs.explanation)

ml.jobs.create_or_update(rai_pipeline(
    Input(type="mltable", path="azureml:churn-train-mltable:1"),
    Input(type="mltable", path="azureml:churn-test-mltable:1")))
```

Component names and parameters follow Microsoft's SDK v2 guide; the gather step's input names should be checked against the current component version in the `azureml` registry. The finished dashboard appears on the model's **Responsible AI** tab in studio. The studio UI can also create dashboards without code.

## Design decisions and trade-offs

| Decision | Guidance |
|---|---|
| **When to run** | For every model with impact on people; as a gate before production and after significant retraining. |
| **Sensitive features** | Include protected attributes for fairness assessment even if not used for prediction (where lawful and governed). |
| **Fairness metric** | Choose based on harm: equal opportunity (false negative parity) vs demographic parity (selection rate) vs error-rate balance; document the rationale. |
| **Explanations for users** | Global explanations for governance; local explanations and counterfactuals for individual recourse. |
| **Causal analysis** | Only with domain expertise; observational data has confounders. |
| **Generative AI** | Use Foundry evaluators and red teaming, not this dashboard. |

## Hands-on

1. Register a churn model trained with MLflow and train/test `MLTable` data assets.
2. Create an RAI dashboard (studio wizard or the pipeline above) with error analysis, explanations and counterfactuals.
3. In error analysis, find the cohort with the highest error rate; inspect its feature distributions.
4. In fairness, compare recall across `region`; note disparities.
5. Generate a scorecard with targets (for example recall ≥ 0.8, disparity ≤ 0.1) and share it.
6. Mitigate (rebalance or add data for the weak cohort), retrain, and compare dashboards.

## Security, cost and reliability notes

- **Sensitive data**: dashboards include data samples and protected attributes; restrict access and handle per privacy policy.
- **Cost**: dashboard generation runs compute jobs (counterfactuals and causal analysis can be heavy); limit components and sample size.
- **Governance**: store scorecards with model versions as audit evidence.
- **Limitations**: explanations approximate model behaviour; fairness metrics depend on group definitions and data quality.

## Common mistakes

| Mistake | Fix |
|---|---|
| Treating overall accuracy as sufficient | Analyse cohorts and fairness |
| Excluding sensitive attributes entirely, hiding bias | Assess fairness with governed sensitive features |
| Reading causal analysis as proof | Validate with domain experts or experiments |
| Using the dashboard for LLM apps | Use Foundry evaluations |
| No documentation of chosen fairness metric | Record rationale in the scorecard/model card |
